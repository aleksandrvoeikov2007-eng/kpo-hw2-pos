# ПОС — Преподавательская оценка студентов

Консольный модуль на Go: студенты, рубрикатор, оценки, итог по весам, статистика и CSV-экспорт. Только стандартная библиотека. Требуется Go 1.22 или новее.

## Запуск

Откройте терминал в папке проекта, где находится `go.mod`:

```sh
go run ./cmd/pos
```

Приложение выводит справку и принимает команды. Изначально ведомость пустая; данные задаются через консоль или файл команд.

Демонстрация в Bash, Linux/macOS или Git Bash:

```sh
go run ./cmd/pos < examples/demo.txt
```

В PowerShell:

```powershell
Get-Content -Encoding utf8 examples/demo.txt | go run ./cmd/pos
```

После демонстрации в текущей папке появляется `results.csv`. Пример вывода находится в [`examples/demo-output.txt`](examples/demo-output.txt), пример CSV — в [`examples/results.csv`](examples/results.csv).

Сборка и проверка:

```sh
go build -o bin/pos ./cmd/pos
go test ./... -race -coverprofile=coverage.out
go tool cover -func=coverage.out
go vet ./...
```

На Windows можно собрать `go build -o bin/pos.exe ./cmd/pos`. Для обычной проверки достаточно `go test ./...`; флаг `-race` дополнительно проверяет гонки и требует поддержки детектора гонок и C-компилятора в окружении.

## Ввод и команды

Одна команда занимает одну строку, поля разделяются `;`. Дробные числа вводятся с точкой. Пробелы по краям полей удаляются. Идентификаторы регистрозависимы: `S1` и `s1` различаются. Названия могут содержать пробелы; поле с точкой с запятой нужно заключить в двойные кавычки. Пустые строки и строки с `#` в начале пропускаются.

| Действие | Формат |
| --- | --- |
| Добавить студента | `student;add;ID;имя` |
| Изменить имя | `student;rename;ID;новое имя` |
| Удалить студента | `student;remove;ID` |
| Список студентов | `students` |
| Добавить критерий | `criterion;add;ID;название;максимум;вес` |
| Изменить критерий | `criterion;update;ID;название;максимум;вес` |
| Удалить критерий | `criterion;remove;ID` |
| Рубрикатор | `criteria` |
| Выставить или исправить оценку | `grade;ID студента;ID критерия;балл` |
| Оценки студента | `grades;ID студента` |
| Отменить оценку | `cancel;ID студента;ID критерия` |
| Итог студента | `total;ID студента` |
| Все итоги и статистика | `totals` |
| Выбрать правило отсутствующих оценок | `policy;zero` или `policy;strict` |
| Экспортировать все итоги | `export;путь.csv` |
| Справка / выход | `help` / `exit` |

Пример ввода:

```text
student;add;S1;Анна Иванова
criterion;add;C1;Практика;10;0.4
criterion;add;C2;Экзамен;20;0.6
grade;S1;C1;8
grade;S1;C2;15
total;S1
export;results.csv
exit
```

Итог в этом примере: **7,70 из 10**. Команды — пользовательский ввод, в исходном коде демонстрационные данные не заданы.

Ошибочная команда выводит причину, не меняет ведомость и не завершает сеанс. Конец ввода или `exit` завершают работу. При ошибке чтения приложение завершается с ненулевым кодом. Длина строки ограничена стандартным лимитом `bufio.Scanner` — около 64 КиБ.

## Правила предметной области

- У студента и критерия непустые ID и имя; повторный ID в соответствующем списке запрещён.
- Максимум критерия — конечное число больше нуля. Вес задаётся долей: **0 < вес <= 1**. Например, 40% вводятся как `0.4`, а не `40`.
- Сумма весов не обязана равняться единице: при расчёте веса нормализуются. Это позволяет добавлять рубрикатор постепенно.
- Балл — конечное число в диапазоне `[0, максимум]`. `NaN`, бесконечность, отрицательные и превышающие максимум баллы отклоняются. Нулевая оценка допустима и отличается от отсутствующей.
- Оценка возможна только существующему студенту и только по критерию текущего рубрикатора.
- Повторная команда `grade` для той же пары студент–критерий исправляет оценку. Проверка нового балла выполняется до замены старого.
- Максимум критерия нельзя уменьшить ниже любой уже выставленной по нему оценки. Изменение веса или допустимое изменение максимума сразу учитывается в следующем расчёте.
- Критерий с оценками нельзя удалить. Сначала нужно отменить эти оценки. Удаление студента удаляет и его оценки.
- Итоги не сохраняются как независимо редактируемые оценки: они рассчитываются из текущей ведомости.

Для критериев с максимумами `mᵢ`, весами `wᵢ` и баллами `sᵢ`:

```text
Итог = 10 × Σ((sᵢ / mᵢ) × wᵢ) / Σ(wᵢ)
```

`zero` — правило по умолчанию: отсутствующий балл считается нулём, но вес критерия остаётся в знаменателе. `strict` — итог не выдаётся, пока не выставлены оценки по всем критериям. Переключение правила не меняет сами оценки. При пустом рубрикаторе итог не определён: приложение просит добавить критерии.

Домен рассчитывает с `float64` без промежуточного округления; консоль и CSV показывают два знака после точки. В численных тестах используется допуск. `totals` выводит средний, минимальный и максимальный итог студентов. При отсутствии студентов статистика не выводится. В строгом режиме общий отчёт и экспорт отклоняются целиком, если хотя бы один студент оценён не полностью.

## DDD

| Понятие | Тип / место | Решение |
| --- | --- | --- |
| Ubiquitous Language | `Student`, `Criterion`, `Evaluation`, `Score`, `Gradebook`, `Result` | Студент, критерий, оценка, балл, ведомость и итог имеют тот же смысл, что в условии |
| Entity | `Student`, `Criterion` | Идентичность задаётся ID; имя или параметры можно изменить без смены идентичности |
| Value Object | `Score` | Балл определяется значением, не имеет собственного ID; проверяется при создании |
| Value Object | `Evaluation` | Неизменяемая запись критерия и балла; принадлежность студенту задаётся внутри ведомости; при исправлении запись заменяется |
| Aggregate Root | `Gradebook` | Ведомость одного курса объединяет студентов, рубрикатор и оценки и охраняет их связи |
| Domain Service | `Calculator` | Итог зависит одновременно от рубрикатора, оценок и правила расчёта |
| Repository | `application.Repository` | Порт загрузки и сохранения агрегата; конкретное хранение находится в адаптере |

Главные инварианты находятся в [`domain/model.go`](internal/domain/model.go) и [`domain/gradebook.go`](internal/domain/gradebook.go), а не в консольном парсере. Поля модели закрыты. Создать допустимый балл можно через `NewScore`, а добавить оценку в ведомость — через `Gradebook.Grade`, который проверяет студента и вызывает фабрику. Ни консоль, ни репозиторий не меняют внутренние коллекции напрямую.

Для одного курса выбран один агрегат: это позволяет проверять существование критерия и диапазон балла в одной операции. В большом многокурсовом приложении границы стоит пересмотреть, но здесь отдельные агрегаты, события и транзакционные координаторы усложнили бы задачу без необходимости.

`Students`, `Criteria` и `Evaluations` возвращают новые списки, отсортированные по ID. Элементы — значения с закрытыми полями. Репозиторий также сохраняет и возвращает глубокие копии ведомости: изменение загруженной копии не меняет сохранённые данные до успешного `Save`.

## Архитектура Ports and Adapters

| Слой | Папка | Ответственность |
| --- | --- | --- |
| Domain | `internal/domain` | Сущности, объекты-значения, агрегат, фабрика и расчёт итогов |
| Application | `internal/application` | Сценарии через `Facade`, порты `Repository` и `ResultExporter`, общий отчёт и экспорт |
| Входной адаптер | `internal/adapters/console` | Команды, парсинг, сообщения пользователю |
| Выходные адаптеры | `internal/adapters/memory`, `internal/adapters/csvexport` | Хранение в памяти и запись CSV |
| Сборка зависимостей | `internal/di`, `cmd/pos` | Провайдеры, контейнер и запуск |

Направление зависимостей: **Console → Application → Domain**. Выходные адаптеры реализуют порты Application и используют доменные типы. Домен импортирует только стандартную библиотеку и ничего не знает о консоли, CSV, файлах или DI. Application не импортирует адаптеры. Контейнер на внешней границе знает конкретные реализации и собирает их вместе.

Ведомость хранится в памяти до завершения процесса. Постоянное хранение не требуется условием: пример с файлом команд позволяет повторить сеанс. CSV содержит только итоговую выгрузку, не является резервной копией ведомости и не используется для импорта. Для сохранения между запусками можно реализовать новый `Repository`, не меняя бизнес-правила и консольные команды.

CSV записывается в UTF-8 с разделителем `;` и заголовком `student_id;student_name;score;graded;total`. Результаты отсортированы по ID студента. Папка назначения должна существовать. Запись сначала выполняется во временный файл в той же папке, затем он переносится по указанному пути; существующий файл заменяется при успешном сохранении. Ошибки файловой системы выводятся пользователю. Неудачный расчёт в строгом режиме вообще не вызывает экспортёр.

## Паттерны GoF

Использован один паттерн из каждой требуемой группы.

| Группа | Паттерн и код | Какую задачу решает |
| --- | --- | --- |
| Порождающий | Фабрика — `EvaluationFactory.Create` в [`domain/model.go`](internal/domain/model.go) | Единая точка создания оценки: ищет критерий в рубрикаторе и создаёт допустимый `Score`. Это простая фабрика в трактовке примера из задания |
| Структурный | Facade — `application.Facade` в [`application/facade.go`](internal/application/facade.go) | Консоль вызывает готовые сценарии; фасад загружает агрегат, выполняет действие, сохраняет его, собирает статистику и передаёт итоги порту экспорта |
| Поведенческий | Strategy — `ScoringStrategy`, `MissingAsZero`, `RequireComplete` в [`domain/calculator.go`](internal/domain/calculator.go) | Смена политики неполной ведомости без изменения агрегата и консольного расчёта: нули за пропуски либо требование полноты |

Фабрика используется при каждом выставлении и исправлении оценки. Фасад используется всеми консольными сценариями. Обе стратегии доступны через `policy` и покрыты тестами. Наследование классов и дополнительный фреймворк для реализации этих паттернов в Go не нужны.

## DI-контейнер

[`di.Container`](internal/di/container.go) принимает `Providers` с фабриками репозитория, экспортёра и стратегии. Метод `Facade()` лениво собирает и кеширует фасад; повторное разрешение возвращает тот же объект с той же ведомостью. `di.Default()` регистрирует репозиторий в памяти, CSV-экспортёр и стратегию `zero`.

Контейнер используется только в точке сборки приложения и в тестах. Домен и фасад получают зависимости через конструкторы и не обращаются к контейнеру. Консоль однопоточная, контейнер и репозиторий рассчитаны на этот режим. Универсальный реестр, reflection и внешняя DI-библиотека не вводились.

## Проверки и демонстрация

Сборка, `go vet ./...`, тесты с `-race` и запуск собранной программы с файлом команд прошли. Общее покрытие операторов — **97,4%**. Пакеты Application, Memory и DI покрыты на 100%; Domain — на 98,7%, Console — на 98,4%, CSV — на 90,5%. Небольшой `main` проверен отдельным запуском программы.

Основные проверки:

- `TestValueObjectsAndEntities`, `TestFactoryChecksRubricAndScore` — диапазоны, конечность чисел, неизвестный критерий.
- `TestGradeCorrectionCancellationAndCurrentTotal` — исправление, отмена и пересчёт; неудачное исправление сохраняет старый балл.
- `TestStrategiesAndNormalizedWeights` — обе стратегии, нормализация весов, изменение максимума и пустой рубрикатор.
- `TestStudentAndCriterionLifecycle`, `TestCopiesDoNotExposeAggregateState` — изменения, удаление, связи и защита внутренних коллекций.
- `TestRepositoryFailureAndFailedMutation` — ошибки репозитория и отсутствие сохранения после недопустимого действия.
- `TestProvidersAreLazyAndDependenciesAreReplaced` — подмена стратегии и экспортёра через DI-контейнер, ленивое создание и повторное разрешение.
- `TestCSVExport`, `TestExportErrorsAndTemporaryCleanup` — содержимое, экранирование, перезапись и ошибки CSV-экспорта.
- `TestEndToEndDemo`, `TestInvalidCommandsAndRecovery`, `TestStrictExportDoesNotOverwriteFile` — сквозной сценарий, ошибки ввода, продолжение сеанса и сохранность файла при отказе расчёта.

В `examples/demo.txt` намеренно предусмотрены **10 отказов**: пустой рубрикатор, два расчёта неполной ведомости в строгом режиме, превышение максимума, неизвестный критерий, неизвестный студент, повторный ID студента, недопустимое уменьшение максимума, удаление критерия с оценками и отрицательный вес. Это проверка обработки ошибок, а не сбои приложения. Остальные команды демонстрируют успешные сценарии.

Финальный результат демонстрации: **Анна — 9,60; Борис — 10,00; средний — 9,80**. Вывод и строки CSV дополнительно проверены после запуска собранной программы.
